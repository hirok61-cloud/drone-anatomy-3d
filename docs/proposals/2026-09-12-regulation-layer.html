ドローンの構造 3D · 行政利用に向けた追加案 A

制度と結びつける層（制度レイヤー）の設計案

3Dで見ている部品や場面に、日本の無人航空機の制度で「どこに関わるか」を一行で重ねる案です。教材はこれまでどおり判定をせず、根拠と確認先を示すところまでにとどめます。実施するかどうかの判断材料としてまとめました。

作成 2026-09-12対象: 国・地方の無人航空機担当職員、登録講習機関、講師状態: 草案（未実装）
共通の決まり（6項目すべてに適用）
① 教材は「該当する・しない」を判定しない。「求められている」「確認する」の言い方で止め、確認先を必ず併記する。
② 制度の記述には基準日を付ける（例: 2026年9月時点）。法改正が多いため、常設のバナーで「最新は国土交通省の案内で確認」を出す。
③ 数値・条文・章番号には出典を付け、出典一覧ページに集約する。
④ 制度タグの文言は data.js の1か所（REG 表）に置き、画面側は表示するだけにする。改正時の直しを1か所で済ませるため。

A1部品ごとの制度タグ

目的
申請書や報告書に出てくる部品名と制度上の要件を、同じ画面で突き合わせられるようにする。新任職員の研修で「この部品はなぜ制度で触れられるのか」を体で覚える。
見せ方
部品の解説パネルに「制度」の行を1つ足す（アイコン ⚖）。行をタップすると根拠と確認先が開く。設定に「制度の注記を出す」トグルを置き、はじめてモードでは既定オフ、くわしく・専門では既定オン。
実装のあたり
data.js に REG = { 部品キー: [{ text, basis, src, url }] }。ui.js の renderDetail() に行を追加。3Dラベルには出さない（情報量が多すぎるため）。
規模
小。文言の確定が主作業で、コードは半日。

注意: 上の「根拠のあたり」は条文番号を書いていません。条番号は改正で動くため、画面には制度名と施行時期だけを出し、条番号は出典一覧ページに置くのが安全です。免除や例外の細部は書かず、「前提つき」「確認する」で止めます。

A2重量区分のライン

目的
制度の説明で最も多く使う数字「100g」「25kg」を、機体の実寸と並べて体感させる。荷物を積むと合計が変わることも同じ画面で見せる。
見せ方
実寸モードの質量バーに、0・100g・この機体（2.4kg）・25kg の目盛りを重ねる。3Dには「100gの機体（手のひらサイズ）」と「25kgの機体（人の背丈ほどの幅）」の淡いシルエットを並べる。人型モデルがあるので大きさの比較が成立する。
文言案
100g未満: 航空法の登録対象ではないが、空港周辺や150m以上など一部の規制は適用される。100g以上: 登録と特定飛行の規制の対象。25kg以上: 許可承認の審査基準がより厳しく、技能証明の限定変更が要る。
実装のあたり
scale.js の renderMassBar() に目盛り、buildGhost() の仕組みで2つのシルエット。ペイロードを足したときに区分の目盛りが近づく演出。
規模
小〜中。

A3教則の章対応

目的
登録講習機関の学科講習の補助教材として、教則のどの項目を扱うのかを明示する。監督する側もカバレッジを一覧で確認できる。
見せ方
各タブ・各カードに小さなチップ「教則 3.3」を付ける。授業モードの印刷シートに章対応の一覧を載せる。講習機関向けに「教則カバレッジ表」の1ページを用意する。
実装のあたり
data.js の PARTS・QUESTIONS・MISHAPS・WHATIF・LESSONS に kyosoku: '3.3' の項目を足す。チップの表示は renderDetail() と各カードの描画に1行ずつ。
規模
小。対応表の確定が主作業。

A4フェイルセーフの場面と制度の対応

目的
「もしも」の5場面は、機体認証の安全基準や許可承認の審査要領がまさに求めている挙動です。場面の最後に「制度ではここが要求されている」を一言足すと、体験が制度理解につながる。
見せ方
各場面の終わりに出る2欄（機体ができること／人がやること）の下に、3つ目の短い行「制度では」を追加する。タップで確認先。
実装のあたり
data.js の WHATIF 各項目に reg: { text, src }。ui.js の onWhatifChanged のカード描画に1行。
規模
小。
場面「制度では」の文言案根拠のあたり
電波が途切れた操縦の電波が途絶したときに帰還・ホバー・着陸のいずれかを自動で行う機能は、機体認証の安全基準と、目視外飛行などの審査で確認される。機体認証の安全基準、許可承認の審査要領
電池が少ない飛行前にバッテリー残量を確認することは飛行前点検の項目。低電圧の警告と自動降下は機体側の安全機能として確認される。教則の飛行前点検、機体認証
GPSを見失った位置を保てない状態でも姿勢を保って操縦できることが求められる。飛行前に衛星の受信状態を確認する。審査要領（安定した飛行の確認）、教則 3.4
風が強い飛行マニュアルでは風速5m/s以上で飛ばさないのが一般的な基準。飛行前に現地の風を測る。標準の飛行マニュアル、教則 5.2 気象
人が近づいた第三者や物件から30m未満は特定飛行。第三者の上空を飛ぶにはカテゴリーIIIの要件（一等技能証明・第一種機体認証・許可承認）が要る。立入管理措置で第三者を入れないのがカテゴリーII。航空法の特定飛行とカテゴリー区分

組み間違いの劇場（プロペラ逆付けなど）には「飛行前点検で見つける項目」であることと、日常点検記録に残す旨を同じ形で添えます。

A5立入管理措置の図解

目的
カテゴリーIIとIIIの違いは、言葉より位置関係の絵で伝わる。人型モデルと床のリングがすでにあるので、追加コストが小さい。
見せ方
新しい場面「人を入れない」を「もしも」に追加。操縦者・補助者・第三者を人型で配置し、床に30mのリングと立入管理区域（コーン・看板のシルエット）を描く。カメラは上から見下ろしと斜めの2段階。
段階1: 補助者と看板で第三者が区域の外にいる（カテゴリーII）。段階2: 第三者が区域に入ってくる → 機体は降りる／飛行を中断する。段階3: 「第三者の上を飛ぶなら」として要件を一覧で示す（カテゴリーIII）。
実装のあたり
whatif.js に motion tachiiri。人型は buildPerson() を複製して3体。リングは GPS 場面の whatif.ring と同じ作り。30mは実寸だと巨大なので、縮尺を画面に明記して 1/10 で描く。
規模
中。1場面の追加と人型の複製。

立入管理措置の具体的な方法は審査要領と飛行マニュアルの記述に従います。図は概念を示すものとし、「看板とコーンを置けばよい」と読める表現は避けます。

A6事故報告の記述例

目的
事故等の報告制度（2022年12月施行）では、報告義務のある事象と、報告に書く内容が決まっている。受付側の職員と報告する側が、同じ部品名・同じ順序で状況を書けるようにする。
見せ方
劇場と「もしも」の最終カードに折りたたみ「報告するなら」を追加。①この事象は報告義務にあたるかの目安（人の死傷・第三者の物件損壊・航空機との衝突や接近・重大インシデント）②報告書の記述例（発生日時、場所、機体の登録記号、飛行の区分、損壊した部位、経過、その後の対応）③報告に至らない不具合は点検整備記録へ、の3点。印刷シートに「報告書メモ」の版を足す。
文言例
損壊部位: 前右プロペラ（欠け）、前右アーム（根元の白化）、着陸脚（曲がり）。経過: 離陸直後に機体が右へ傾き、高度約1mで横転して着地。第三者・物件への被害なし。対応: 飛行を中止し、プロペラの取り付け向きを確認したところ前右が逆向きだった。
実装のあたり
data.js の MISHAPS・WHATIF に report: { duty, example }。lesson.js の印刷シートに版を1つ。
規模
小〜中。文例の監修に時間をかける。

「報告義務にあたるか」は最終的に制度の定義に従います。教材は「目安」と明記し、判断は国土交通省の案内と報告窓口（DIPS2.0）で確認するよう促します。運輸安全委員会の調査対象になる事故があることも一文で触れます。

着手順の案
