# ドローンショーの「形」の作り方（作者向けの手引き）

夜のドローンショーで、入力された言葉（例:「ドラゴン」）を**光の点でできた形**として見せる。
形は `src/shapes/<id>.json` に1つずつ書く。エンジン（`src/dshapes.js`）が下絵を点に変え、動きをつける。

- 機体の数は **1200 / 2200 / 3200**（端末の画質設定で変わる）。**1200機・スマホの小さな画面で何の形か分かること**が合格ラインです。
- 機体は光るだけで、黒は出せません。背景は夜空（ほぼ黒）。**色は光の色**として選びます。
- 特定の作品のキャラクター（アニメ・ゲーム・企業のマスコット等）は作りません。**一般的なモチーフを自分の絵として**描きます。

## 1. まず動かす

開発サーバー（`http://127.0.0.1:8941`）は起動済みです。確認は必ず画像で行います。

```bash
cd "/Users/kameda_hirofumi/Desktop/ドローン関連/ドローン構造3D"
tools/shapelab.sh docs/review/shapes/<id>.png "shape=<id>"      # 約3秒。PNG を Read で開いて自分の目で見る（小さめの画像）
tools/shapelab.sh docs/review/shapes/<id>.png "shape=<id>&z=1"  # 細部まで見たいときだけ（大きい画像。読む量が倍以上になるので、ここぞという時に）
tools/shapelab.sh --report "shape=<id>"                          # 報告だけを文字で見る（警告・部品ごとの点の数・縦横比）。画像を読むより桁違いに安い
```

**進め方のこつ**: まず `--report` で警告をゼロにし、それから画像で見た目を確かめる。画像を読むのは「見た目の判断」が要るときだけにする。

画像には「元の絵／3200機／1200機（大きく）／1200機（スマホ実寸）／動きの5コマ／重ね描き」と、
部品ごとの点の数・警告が出ます。**警告（橙）とエラー（赤）が無くなるまで直してください。** 下絵の上の桃色の印は「細すぎるすき間」（平行に続く幅4未満の溝）の場所です。V字の谷やかどは数えません。水色の「参考」は直さなくても合格です。
お手本: `src/shapes/butterfly.json`（左右対称＋羽ばたき）、`src/shapes/snake.json`（帯＋うねり）。

## 2. ファイルの形

```json
{
  "id": "butterfly",                     // 半角英数字。ファイル名と同じ
  "name": "ちょう",                      // 画面に出る名前（ひらがな・カタカナ中心で短く）
  "keys": ["蝶", "ちょうちょ", "バタフライ", "butterfly", "🦋"],
  "vb": [0, 0, 100, 100],               // 下絵の座標の範囲 [x, y, 幅, 高さ]。y は下向き
  "paths": { "spine": [[x,y], ...] },   // （任意）名前をつけた線。band / fins / spine から名前で使える
  "parts": [ ... ],                     // 部品。**あとに書いたものほど手前**
  "anim":  [ ... ]                      // 動き
}
```

`keys` は「この言葉を打ったらこの形」の一覧。ひらがな・カタカナ・全角半角・大文字小文字・「！」などの違いは
エンジンが吸収するので、**読みの違うもの・漢字・英語・絵文字**を入れてください（例:「りゅう」「竜」「龍」「ドラゴン」「dragon」「🐉」）。
ほかの形と同じ言葉を取り合わないこと（`grep -l "言葉" src/shapes/*.json` で確認）。

### 部品（parts）

形の指定はどれか1つ:

| 書き方 | 意味 |
|---|---|
| `"d": "M… C… Z"` | SVG のパス |
| `"circle": [cx, cy, r]` / `"ellipse": [cx, cy, rx, ry, 回転°]` | 円・楕円 |
| `"rect": [x, y, w, h, 角丸]` / `"poly": [x,y, x,y, …]` | 四角・多角形 |
| `"star": [cx, cy, 外R, 内r, 頂点の数, 回転°]` | 星形 |
| `"arc": [cx, cy, r, 開始°, 終了°]` | 円弧（線で使う。0°=右、時計回り）。角度を省くと一周＝輪（天使の輪・浮き輪・タイヤ） |
| `"line": [x,y, x,y, …]` | 折れ線（線で使う） |
| `"band": { "path": 線, "r": [太さの半分…], "off": ずらし, "from": 0, "to": 1 }` | **太さの変わるなめらかな帯**。胴・しっぽ・首・触手・角・枝・虹・三日月 |
| `"fins": { "path": 線, "from", "to", "count", "h": [高さ…], "w": 幅, "side": 1か-1, "lean": 後ろへの傾き, "r": [帯の太さ…] }` | 線に沿って並ぶ三角。背びれ・とげ・たてがみ・太陽の光 |

- `band` / `fins` の `path` は制御点の並び `[[x,y],…]`（なめらかな曲線でつながれる）か、`paths` につけた名前。
  `r` `h` `off` は線の始点→終点に沿った値の並び（何個でもよい。間はなめらかに補間）。
  `side` と `off` の正の向きは「進む向きに対して右手側」（左→右へ進む線なら**下**）。`fins` の `r` に帯と同じ太さを渡すと、帯の表面から生える。
  `fins` の `r` は**線全体（0〜1）に沿った値**として読まれる（帯が線の全長を使っている前提）。帯のほうに `from`/`to` を付けたときは、`fins` に `"rspan": [from, to]` を足して合わせる。
- **帯の上の模様は、同じ帯を切り出して作る。** 体を `band` で描いたら、同じ `path`・同じ `r` の一部を `from`/`to` で切り出した `band` を上に重ねる（`r` の並びの区切りに `from`/`to` を合わせる）。
  体の断面とぴったり一致し、はみ出しも隙間もできない（さかなの白い帯がこの方法）。ふつうに模様を重ねると必ず輪郭からはみ出す。
- **ひれ・耳・しっぽなど体から生える部品は、体より先に書いて付け根を体で隠す。** あとから重ねると、付け根に細いすき間ができて光の塊や割れ目になる。
- 塗り: `"c": "#rrggbb"`。塗りの規則は `"rule": "evenodd"` も選べる（`cut` と組み合わせると「この輪郭の外を全部消す」が書ける）。グラデーションは `"c2"` と `"g": [x0,y0,x1,y1]`（直線）または `"gr": [cx,cy,半径]`（放射）。
- 線だけの部品: `"s": "#rrggbb", "sw": 太さ`（`c` は書かない）。ひげ・触角・口・弦など。**sw は 1.6 以上**。線は単色（グラデーションは塗りの部品だけ。色の変わる光の筋は、細いくさび形の塗りで描く）。
- `"mirror": 50` … x=50 を軸に左右を写した部品を自動で足す。左右対称の絵は片側だけ描けばよい。**写しの tag は元と同じ**になる。左右を別々に動かしたいときは部品に `"mtag": "earR"` を書く（動きの `mtags` は、この mtag を持つ部品を指す）。
- `"tag": "wing"` … 動きをかける部位の名前。
- `"w": 2` … この部品だけ点を濃くする（0.5〜4）。**目・口などの小さくて大事な部品は 1.6〜2.5**。
- `"edge": false` … 手前に重ねても境目を線として縁取らない（ほおの赤み、腹の色など、ふんわり色だけ変えたい面）。
  **ハイライトや白い芯には使わない。** ほかの部品の完全に内側にあると輪郭の点が1つも置かれず、「灰色のもや」にしかならない。光らせたい所は、縁取りのある細い帯や小さな部品にする。
- `"cut": true` … その形でくり抜く（穴）。
- `"b": 1.2` … 明るさの倍率。すでに最大の成分を持つ色（#ff…）は、これ以上は白へ寄るだけ（色相は保たれる）。広い面の色を戻したいときは `w` を 1.2 前後に上げるほうが効く。

### 点はこう置かれる（絵の描き方に直結します）

1. **すべての部品の境目**（外周＋手前の部品の縁）に、点が等間隔で1列に並ぶ。
2. 残りの面は、六方格子でまばらに埋まる。色はその場所のいちばん手前の部品の色。
3. 点の間隔は、1200機で**形の半分の大きさの約5%**（vb が100なら 2.5〜3）。3200機で約3%。

だから:

- **輪郭がすべて。** シルエットだけで何か分かる、象徴的な向き（真横・真正面・真上）で描く。遠近法は使わない。
- **部品は 8〜25 個まで。** 境目が多いほど輪郭に機体を取られて、面が薄くなる。細かい模様を重ねない。
- **小さな部品は消える。** 直径が 5（vb=100のとき）より小さい部品は1200機で 1〜3 点にしかならない。目は半径 3 以上＋`w`。
- **細い隙間・細い突起も消える。** 幅 4 未満の隙間はつぶれて光の塊になる。脚と脚の間、指の間は思い切って空ける。
- **縦横比は 0.7〜1.5。** 横長すぎる形はスマホの縦画面で小さくなる。vb いっぱいに大きく描く。
- 曲線はなめらかに。ガタついたパスは点の列もガタつく。**`band` と円・楕円を積極的に使う**（手書きのパスより確実にきれい）。
- `band` の曲がりは、**曲がりの半径 ≧ 太さ(r)の2.5倍**。きつく曲げると内側で点が重なって光の塊になる。

### 色

- 光の点は**芯が白く飛ぶ**。淡い色（パステル）はほぼ白に見える。**彩度の高い、はっきりした色**を使う
  （例: 黄 `#ffd21f`、橙 `#ff8a1f`、赤 `#ff3b4e`、桃 `#ff5fa2`、紫 `#a66bff`、青 `#3d8bff`、水 `#2fd6ff`、緑 `#35e07a`、白 `#ffffff`）。
- **暗い色は使わない。** 明るさ 0.24 未満は「弱く灯した青灰」に置き換わる（黒い瞳・影として少しだけ使うのは可）。
- となり合う部品は**色相を変える**（同じ色相の濃淡では境目が見えない）。1つの形は 2〜5 色。
- 白は強い。目の白・歯・雪・ハイライトなど、いちばん見せたい所に使う。
- **大きな単色の面は、思ったより暗く見える**（面の内側は点がまばらなため）。広い面ほど明るめ・鮮やかめの色を選ぶ。橙は茶色に、青は紺に沈みやすい。
- 放射状の形（花火・太陽の光・矢車）は**18本まで**。それより多いと、となりとの谷が細くなって光の塊になる。

## 3. 動き（anim）

長さは vb の単位、角度はラジアン、`hz` は1秒あたりの回数。`tags` を省くと形全体にかかる。
**ゆっくり・小さく**（0.2〜1.2Hz）。どのコマで止めても何の形か分かること。動きを含む外接が止まった形の1.35倍を超えると警告。

| type | 何が起きる | おもな値 |
|---|---|---|
| `spine` | **背骨に沿ってうねる。** 点は背骨に結びつき、体の太さ・模様・脚ごと運ばれる。龍・蛇・魚・しっぽ・触手・リボン・旗 | `path`（線か名前）, `amp` 振れ幅, `k` 波の数(1.5), `hz`(0.5), `head` 始点側の振れの割合(0.12), `pow`, `phase` 0〜1（足や触手を1本ずつずらすとき） |
| `flap` | 羽ばたき。`hinge` の縦線を軸に横幅が縮んで戻る（畳んだぶん暗くなる） | `hinge:[x,y]`, `amp` 0〜1(0.65), `lift`, `hz` |
| `swing` | 支点まわりに揺れる。腕・脚・しっぽ・耳・振り子 | `pivot:[x,y]`, `amp` 角度(0.2), `hz`, `phase` 0〜1, `r` 根元を固くする距離, `k` 先へ遅れて伝わる度合い, `bias` |
| `sway` | 根元は動かず、上ほど大きく揺れる。木・花・草・炎。**支点より上だけが揺れる**（下へ伸びる噴射炎やぶら下がる物は `swing` を使う） | `pivot`（省略時は下端の中央）, `amp` 角度(0.06), `hz` |
| `swim` | 頭→尾へ波が伝わる（形全体を横向きの魚として扱う簡易版） | `amp`, `k`, `hz`, `head:"left"か"right"` |
| `wave` | はためき。留めた側は動かない | `anchor:"left/right/top/bottom/none"`, `amp`, `k`, `hz` |
| `spin` | 回り続ける。風車・車輪・プロペラ・惑星の輪 | `pivot`, `hz`（0.05〜0.3）, `dir:-1` で逆 |
| `pulse` | 拡大縮小。`beat:true` で心臓の二つ打ち。`"sx": true` で**横だけ**、`"sy": true` で**縦だけ**伸縮（回るローター、まばたき） | `pivot`, `amp` 割合(0.06), `hz` |
| `bob` | ふわふわ上下（`ax` で左右にも） | `amp`, `ax`, `hz` |
| `hop` | 跳ねる（下端を地面として、着地でつぶれる） | `amp`, `hz` |
| `orbit` | 小さな円や楕円を描いて動く（月・衛星・蜂） | `r`, `ry`, `hz` |
| `shift` | 直線の往復（目玉、ピストン） | `ax`, `ay`, `hz` |
| `twinkle` | 1点ずつばらばらに瞬く（星・雪・イルミネーション・火花） | `depth` 0〜1(0.6), `hz` |
| `blink` | その部位がそろって明滅（灯台・信号・目の光） | `depth`, `hz`, `phase` |
| `chase` | 光が流れる（`pivot` のまわりを回る／`axis:"x"` で横に流れる）。まわりを回すときの `k` は**整数**（半端だと継ぎ目が出る） | `k` 縞の数, `hz`, `depth` |

- 同じ tag に複数の動きをかけられる（上から順）。`spine` は必ず最初にかかる。
- `spine` の点は「いちばん近い背骨の場所」に結びつく。**背骨の線が自分自身に近づく配置（とぐろ・交差・折り返しが体の太さの3倍より近い）は避ける**。
  近いと、となりの胴に結びついた点が動きでちぎれる。頭・脚・ひれなど胴から生える部品も同じ tag に入れて、一緒に運ばせる。
- **動く部品は、付け根が支点の上に来るように描く**（離れていると、動いたときに体からちぎれて見える）。
- 左右の脚や腕を交互に振るには、同じ `swing` を `phase: 0` と `phase: 0.5` で2つ書く。
- **左右対称の動きは `"mirror": 50` で写せる。** `{ "type": "swing", "tags": ["earL"], "pivot": [38, 22], "amp": 0.2, "mirror": 50, "mtags": ["earR"], "mphase": 0.5 }` と書くと、
  支点を x=50 で写し、回る向きも逆にした動きが `earR` に足される（`mphase` は写した側の位相のずらし。省略すれば左右同時）。
- `spine` に `"bind": { "legs": [0.6, 1.0] }` を足すと、その tag を結びつける背骨の範囲を絞れる（曲がりの内側の脚が、向かいの胴に結びつくのを防ぐ）。
- 細い線（幅が点の間隔ほどしかない線・脚・角）は、自動的にまん中へ1列で置かれる。
- 全体に `bob` を小さく足すと「浮いている」感じが出る。
- `phase`（0〜1）はどの動きにも効く。同じ動きを位相違いで並べると、花びら・足・風船がばらばらに動く。
