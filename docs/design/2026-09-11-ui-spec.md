# UI設計メモ（2026-09-11 UI/UXエージェントの助言を採用したもの）

## 土台: ドックを「やること」4タブに
- タブ: みる / とばす / つかう / もしも。文脈行はタブごとに最大6コントロール。
- 視点・ラベル・全画面はステージ右下の縦アイコン列(44px)へ。
- モーターは「▶回す／■止める」1トグル。速度3段は「くわしく」時のみ。
- `--dock-h` は ResizeObserver で実測値をセット。
- 説明面は `#noteCard` 1つに統一（原理の解説／質問の答え／用途の説明／シアター字幕）。
- トーストは1レーン（トップバー下・中央・同時1件・role=status）。

## 排他ルール
- とばす に入る: 分解>0→0へ、断面→通常へ。
- もしも 再生中: 他タブ・質問・スティック・部品選択は無効。Esc=やめる。
- 質問の act 実行時はスティック操作を中断。

## B6 重さ・お金・重心（パッケージ⑥ / 2026-09-11実装）
- 入口: つかうタブの文脈行「重さ・お金」トグル（`#scaleBtn`）。用途チップと排他。タブを離れると自動で解除。
- 入ると機体はホバー（`S.power=0.5`・free）し、積み上げバー（`#massBar`、デスクトップは左上・スマホはドック上の横バー）と重心マーカー、人型スケール（スマホ以外）が出る。
- 質量は `MASS`（親部品のみ40→31区分、内部部品は親に含める）。はじめてでは SIMPLE_KEYS 8 + その他 の9区分に丸める。合計 2.42 kg。
- モーター%バッジは「負担率」= (総重量/基準重量) × 前後配分 × 左右配分。負担率 1.35 超で赤（`.mbadge.over`）＋注記。
- バッテリーと荷物ゴーストは前後±45mmドラッグ可（`scaleTryDrag`、`pointerdown` の最初にフック）。重心は「設計上のつり合い点」からのずれで測る（`scale.cg0`）。
- ¥ボタンで3Dラベルを参考価格に差し替え、合計と注記（年・出典の但し書き）を必ず出す。
- 排他の追加: `setUse(id)` は id 指定時に重さモードを解除。`setTab` は use 以外へ移ると解除。

## B8 生きている機体と、みんなの土台（パッケージ⑧ / 2026-09-12実装）
- `S.alive`（設定「浮かせておく」・永続）。みるタブで何も選んでいない・分解0・通常モード・質問/シアター/もしも/授業/重さ/用途でないとき、0.8秒後にホバー（`alive.on`）。条件が外れると即着陸。とばすタブへ移ったときは飛行を引き継ぐ（着陸させない）。
- 生きている間もラベルを出し（`updateLabels` の live 判定）、%バッジと推力矢印は出さない（はじく・押すときだけ矢印）。ポインタの方へ yaw ±4° だけ向く（`body.lookYaw`、`stepFree` で目標を差し替え）。10秒放置で自動回転。軽量画質(0〜1)では強制オフ＋注記。
- 生きている機体を軽くタップ（8px未満・350ms未満）すると選択になる（フリックは従来どおり）。
- 大きく読む: `#bigBtn`（視点列）と設定トグル。文字1.18倍・3Dラベルを消し・`#bigBand` に選択中/ホバー中の部品名を1つだけ（28px、スマホ22px）。
  - 1.18倍が効くのは **`font-size: calc(Npx * var(--fs, 1))` と書いた規則だけ**。読む文字（`#detail` 一式・`#noteBody`・`.analogy`/`.tipbox`/`.spec`/`.trivia`/`.two-col`、授業の `.step .say`、3Dラベル `.lbl`、`#askList`、`#coach`）はすべて `--fs` を掛ける。**ドック・タブ・視点列・設定ポップの操作系は掛けない**（横一列が崩れる）。2026-09-12までこの掛け忘れで解説文がまったく大きくならなかった。
  - スマホ(≤1100px)では `#bigBand` を **シートの上**に出す（`bottom: calc(var(--sheet-h, var(--dock-h)) + 8px)` / `z-index: 15`）。`--sheet-h` は ui.js の `fold()` が開いているシートの `offsetHeight` から入れる。横向き（≤520px高）はシートが画面いっぱいなので `body.sheet-open #bigBand { display: none }`、かつ `bottomCover()` は帯を数えない（数えると機体が極端に小さくなる）。
- 言語: `S.lang ∈ ja/easy/en`（設定の先頭）。段階1 = `[data-i18n]` のUI文字・8部品の名前/役割/たとえ・12質問。40部品の解説は日本語のまま「— Japanese only —」を付ける。`partName()/partRole()/qText()/t()` を経由する。
- 読み上げ: `speak()`（Web Speech）。解説見出し・大きく帯・質問カードの🔊、設定「選ぶと自動で読む」。iOS のためクリックハンドラ内で直接呼ぶ。

## スマホ・横向きの決まりごと（2026-09-12 総点検）
- 画面の分岐は3つ: `@media (max-width: 1100px)`（右パネルをボトムシートに）/ `@media (max-width: 760px), (max-height: 520px)`（ドック・視点列の詰め）/ `@media (pointer: coarse)`（44pt・入力欄16px下限）。**coarse ブロックは CSS の末尾**に置く（前に置くと後続の宣言に負ける）。
- 視点列 `#viewCol` は**1段に収める**（`flex: 1 1 0` で幅を分け合い、全画面ボタン `#fsBtn` は消す）。折り返すと空の段が3Dを隠す（2026-09-12 の録画で発覚）。`#viewCol #fsBtn` と詳細度を上げないと `#viewCol button { display: grid }` に負ける。
- シートは `#inspector` / `#lesson` / `#expert` が同じ挙動（`bindSheet()` 1本、ui.js）。**3段デテント**: `.peek`（`max(150px, 21vh)`・つまみ＋見出しだけ。機体を眺めながら部品を突つく段）/ open（部品 56vh・専門 46vh）/ `.tall`（80vh）。つまみを上下にはじくと1段ずつ、peek からさらに下げると閉じる、つまみのタップで peek ⇄ open。**高さ ≤520px（横向き）ではすべて `height: calc(100% - 12px)`**。`✕` は 1100px 以下でだけ出す。
- シートが open/tall のときは `body.sheet-open` で視点列を畳み、tall では `body.sheet-tall` でタイトルバーも畳む（MutationObserver が class を見て付ける）。peek では戻す。
- **「帯が画面」の約束**（engine.js `applyBand` / `topCover` / `bottomCover`）: 上のバーと下のシートに挟まれた帯の中心へ `setViewOffset` で画をずらし、帯が狭まった比率ぶんカメラを引く（広がれば寄る）。`focusOn` は帯の高さで縦の必要距離を決め、`camMax()` にも `bandK()` を掛ける（掛けないと `stepCamera` の上限戻しに押し込まれる）。台本（劇場・もしも）の間は触らない。`topCover` は transition を待たず body の class で畳んだ後の形を測る。
- `env(safe-area-inset-*)` を `--sal/--sar/--sab/--sat` に持ち、`#topbar` `#dock` `#viewCol` `.popover` `#noteCard` `#massBar` の位置に足す。
- 入力欄は `font-size: max(16px, …)`（iOS のフォーカス拡大を防ぐ）。`button` 等に `touch-action: manipulation` と `-webkit-user-select: none`、`.grabber` に `touch-action: none`。
- カメラ: 引ける上限は `camMax() = 3.2 × viewScale()`。台本の引き（`flyTo`）はその場で上限を広げ、場面を抜けるときは `camHome()` で機体の枠に戻す。**固定値で clamp しない**（縦画面で場面が枠に入らなくなる）。

## B18 機体のカメラから見る（一人称視点／2026-09-13実装）
- 見え方の列に `data-v="fpv"`。`src/fpv.js`。カメラを増やさず、**機体のカメラ部品の世界姿勢を main camera に写す**（GTAO・輪郭線・接地影がそのまま効く）。レンズの前 0.045m へ出して筐体の中から写さない。
- **並び順が肝**。`applyBody(dt)` の**あと**に `updateGimbal()` → `stepFpv(dt)` を呼ぶ。前に呼ぶと本体の姿勢が1コマ遅れ、ジンバルが効いていないように見える（最初の実装でここを間違えた）。
- ジンバルは `c.rotation.set(ex, pan, ez, 'YXZ')`。`ex = (水平を保つ ? -body.tz : 0) + tilt`、`ez = 水平を保つ ? body.tx : 0`。同じコマで入切を比べると、機体ロール4.3°に対しカメラは 入=-0.15° / 切=-4.37°。可動域（パン±95°・チルト+22〜-88°）の丸めは `updateGimbal()` の中で1回だけ行う（共有リンクなどドラッグ以外から入ることがある）。
- **舞台がないとジンバルも画角も分からない**。`fpvStage` が地平線・離着陸場・距離の輪（3/10/20m）・距離の文字・コーン4本・実寸の人型を出す。
  - 遠くの地面は半径4〜30mのリング。**材質は床と同じ**（MeshPhysicalMaterial、色は `THEME[].ground`）にして、遠さは**頂点色の掛け算（かすみ）だけ**で出す。色を別に決めると必ず継ぎ目が出る。かすみの強さは暗いテーマ ×3.1、明るいテーマ ×0.70。
  - かすみの効き具合は**画面上で等間隔**になるよう `u = (1/4 - 1/r) / (1/4 - 1/30)`。半径に対する `t^0.42` のような曲線だと、内側の縁だけ急に明るくなって段差に見える。
  - 距離の輪は**遠いほど太く**（幅 = 0.04×(r/3)²）。見かけの太さは 幅×目の高さ÷距離² なので、同じ太さだと10m・20mの輪が1px未満になり点線に見える。
  - 床の文字も同じ理由で**あらかじめ縦に伸ばす**（滑走路の数字と同じ）。幅 0.62×k^0.85、高さ 0.30×k^1.5（k = r/3）。完全補正（k²）にすると10mの文字が画面を埋める。
  - **縦長の画面は横の画角が26°しかない**。`fpvTall()`（横÷縦 < 1.05）で、人型 (-0.9, -9.0)／コーン方位±11°／初期チルト -14° に置き直す（横長は (-1.1, -5.4)／±20°／-12°）。resize でも置き直す。伏せすぎると地平線が画面外に出てジンバルの実演ができないので -14° まで。
- **床を広げるときは `groundScale(k)`（= `scale.set(k, k, 1)`）を使う。** scale は回転より先にローカル軸へ効くので、`set(k, 1, k)` と書くと前後だけ伸びない楕円になり、前方2.8mで地面が切れる。もしもの4場面も同じ誤りだったので合わせて直した。
- 画面の構成: 上に数値（対地高度・対地速度・機首の方位／ピッチ・ロール・パン・チルト・画角）、下にボタン（ジンバル・スティック・外から見る）と法令の注記。**数値には必ず下地を敷く**（`rgba(8,12,18,.6)` ＋ blur）。明るいテーマや白い被写体の上では、影だけの白文字は読めない。
- FPVでは `#ctx`（ドックの操作列）と `#viewCol` を隠す。映像が広がり、`--dock-h` も自動で縮む。戻り道は「外から見る」と Esc。`syncDockH()` を入退場で直接呼ぶ（ResizeObserver は1コマ遅れる）。
- **スティックは送信機と同じく左右のすみへ**（`body.fpv #sticks` を space-between）。広い画面は注記をその間に、760px以下はその上に置く。高度は `stepFree` のスロットル係数を FPV のとき 0.10 → 0.55 にして 0.5〜1.6m を動かす（高度計が動かないと数字の意味が伝わらない）。
- 法令の注記は**この映像は「目視」に含まれない**の一文に絞る（教則第5版 3.1.2）。床の輪の説明は入口のトーストへ。
- 検証は `docs/tests/pE-fpv.js`。数値・重なり（数値／操作／スティック／ドック／タイトル）・ジンバルの入切・可動域・復帰・テーマ追従を見る。

**ジンバルはオイラー角を足し引きしてはいけない。** `rotation.set(-body.tz + tilt, pan, body.tx, 'YXZ')` は `Ry(pan)·Rx(…)·Rz(…)` なので、**打ち消しがパンより後ろ（振った先の座標系）**に入る。パン0°では効いて見えるが、パン95°では画面が21.7°傾く。正しくは「親の世界姿勢の逆 × 望みの世界姿勢」:
```js
c.parent.getWorldQuaternion(q); const f = v.set(0,0,-1).applyQuaternion(q);
const yaw = Math.atan2(-f.x, -f.z);                       // ヨーだけは機体に追随
c.quaternion.copy(q).invert().multiply(q2.setFromEuler(e.set(tilt, yaw + pan, 0, 'YXZ')));
```
実測: 機体ロール7.6°に対し、パン0/45/95°のいずれでも画面の傾きは0.00°。ピッチとロールが同時でも0.00°。

**「同時に1つ」に一人称視点も入れる。** FPV中もドックのタブは押せる。`setTab` は電源を切るので、映像の中で機体が着陸し、操作列は隠れたまま戻れなくなっていた（スマホでは復帰不能）。`setTab` の先頭と `stopOthers()` で `fpvExit()` を呼び、Esc とスペースにも分岐を足す。場面（劇場・もしも・降ろし方）の裏でFPVに入ると舞台が出ないままだったのも、これで塞がる。

**`segSet` は data 属性を持つボタンだけを見る。** `$$('button', seg)` だと、視点列の「名」「大」「🔗」まで `on` を外していた。`$$('button[data-' + attr + ']', seg)` に限定。

**aria-live のカードは丸ごと描き直さない。** 降ろし方は位相が変わるたびに `renderNote` を呼び、長い注記まで読み上げ直していた。`#descBody` と `#noteActions` だけ差し替える（`renderNoteActions()` を切り出した）。逆引き（B16）と同じ直し方。

**説明カードのボタンは折り返しの外に出さない。** `#noteCard` は `max-height` + `overflow-y` なので、VRSの「横へ逃がす」が画面外にあった（402×874で37px下、文字を大きくすると152px下）。`#noteCard[data-kind=descent]` を flex 列にして、値（sticky）と操作（下端固定）を常に見せ、本文だけ送る。

**`--dock-h` は操作列の中身で伸びる。** 1024×500 の「とばす」タブでは 130→202px になり、カードがタイトルバーの裏へ回って閉じるボタンが押せなかった。`max-height: min(46vh, calc(100vh - var(--dock-h) - 122px - var(--sat)))` で上を止める。

**ダークに `--warn` などが無かった。** `.vals b`（「渦に入った」）が 2.76:1。ダークのブロックに `--warn/--ok/--red` を足す。`.chips button.on` の白on橙も 3.1:1 だったので `accent-soft + 枠` に変更。

**`prefers-reduced-motion` で `animation-duration: .01s` は危険。** `infinite` のものが160倍速で回り続ける。`animation: none` にして、読み込みのスピナーだけ例外にする。

**教則に照らした文言の直し**（原文と突き合わせた結果）:
- 目視の注記に但し書きが要る。「双眼鏡やモニター（FPVを含む）や**補助者による監視**は含まない。**ただし残量確認などで一時的にモニターを見るのは目視飛行の範囲内**」（3.1.2(2)2)b.）。前者だけだと逆を覚える。

- 床の輪 3m は〔一等〕の運航計画の例（6.3）。**二等の共通ルールではない**ので、そう書く。

## B19 空もよう（教則第5版 6.2 気象／2026-09-13実装）
- とばすタブの `#skyChips`（晴れ・温暖前線・寒冷前線・海風・ダウンバースト・霧）。`src/weather.js`、文言と数値は `data.js` の `WEATHER`。
- **場面ではなく「場」**。劇場・もしも・降ろし方と違い、選んだあとはそのまま飛ばせる。カードの ✕ では閉じるだけで空は残り、戻すのはチップの再押下か「空をもどす」。ただし場面を始めると `stopOthers` が空をもどす（場面は自前の空を使うため）。一人称視点だけは例外で、空もようのまま入れる。
- **空は背景球のシェーダに乗せる**（`engine.js` の `backdropMat`）。雲の座標は視線を雲底の面と交わらせて作るが、割る値は真の `1/y` ではなく `y + 0.26`。この教材の視点はほぼ水平で、真の遠近だと地平線際が潰れて模様が消える。
  - `uCloud`（雲量）・`uWall`（地平線際だけ雲量を上げる＝前線の壁）・`uSharp`（縁の硬さ）・`uScale`（大きさ）・`uHaze`（かすみ）・`uDrift`（流れ）。`uOct` は品質段階が低い端末で 5→3（全画面のピクセルシェーダなので効く）。
  - **雲は1段のしきい値だと切り絵になる**。`thick`（濃さ）で色を暗くし、縁を `pow(1-thick,3)` で明るくすると立体に見える。
- **風は physics に外乱として渡すだけ**。抗力を `dragH * (v - W)` にすると、位置を保つ制御が働いて機体は風上へ傾いて釣り合う（実機と同じ）。傾きの大きさがそのまま風速を語るので、数値を見なくても強さが分かる。
  - **スティックなしの傾き上限を、風の中だけ 11°→22° にする。** 11°では g·tan11°=1.9m/s² しか出せず、風速3m/sの抗力2.4m/s²に負けて機体が7〜11m流れていった。22°なら4.0m/s²まで耐え、5m/sを超えると流される。
  - 高度は `(py/1.0)^alpha` で上空ほど強い（地表の粗度 alpha が大きいほど差が大きい）。教則の「上空では強く、地表に近づくほど弱い」。
  - 空もようのときのホバー高度は 0.50m（既定の 0.06m では風の影響が見えない）。
- **ダウンバーストは中心が通り過ぎる**。`burstX` を -2.0→+2.0 に動かすと、機体から見て 向かい風 → 真下の下降流で高度を失う → 追い風 の順になる（教則の記述そのもの）。実測で高度 0.50→0.08m、風の x 成分が +2.0→-1.4 に反転。柱と広がる輪で見せる。
- **吹き流し**を置く。実際の飛行現場にもあり、角度だけで風速が読める（5.5m/sでほぼ水平）。カメラの手前に置くと画面の1/3を占めるので奥（0.95, -0.95）へ。
- **遠くの地面は一人称視点と共用**（`farGround`）。床（半径2.8m）だけだと雲の下端が宙に浮く。**内径は 2.6m**（床と重ねる）。4mにすると床との隙間から背景の下半分がのぞいて、地平線の下に暗い帯が出る。色は `groundMat.color` をそのまま複製する（空もようは床の色も変えるため）。
- 雨は**点ではなく線分**（`LineSegments`）。点だと雪に見える。風が強いほど斜めになる。
- **注視点は機体に追従させない。** OrbitControls は target を動かすとカメラも一緒に平行移動するので、風で流れるたびに画の距離が変わってしまう。機体は位置保持で±0.3m程度に収まる。
- 数値は「10分平均」「瞬間（突風込み）」「機体の高さでの実際の風速」を分けて出す。風力はビューフォート階級（0〜12の13階級）。
- **「風速5m/s以上は中止」は書かない。** これは多数の者の集合する催しの上空を飛ぶ場合の要件（教則3.1.1）で、一般の飛行の基準ではない。判断は「降雨・降雪・霧・雷鳴のときは延期や中止が望ましい」（6.2）と、取扱説明書の運用可能な範囲で書く。
- 検証は `docs/tests/pF-weather.js`。

## B20 夜のドローンショー（2026-09-13実装）
- とばすタブの `#showBtn`。`src/dshow.js`、制度の文言は `data.js` の `DSHOW_REG`。**教則が「多数の者の集合する催し」の該当する例として名指ししている場面そのもの**（3.1.2(2)2)d.）で、夜間（3.1.2／4.2.1／6.4.1）と重なる。エンタメと制度が同じ絵の上に乗る、この教材でいちばん贅沢な場面。

  - **教則は条文番号をほとんど書いていない**（催し・夜間の「法132条の86第2項」は審査要領が出典）。条文を引かず「教則にこう書かれている」で止める。
  - カテゴリーⅡA＝**技能証明と機体認証があっても**許可・承認が要る。ここが受講者の最大の誤解。

## B21 ドローンショーの作り直し（機数・見え方・専用機／2026-09-13実装）

「エンタメの見せ場なので質を上げてほしい」「ショーの機体は小型で灯り専門の別物のはず」「スマホで見えにくい・文字が被る」への対応。
演出設計・光の描き方・実機調査で別々にエージェントを組み、その指摘を実装に落とした。

### 1. 動きは頂点シェーダへ（`src/dshow.js`）
以前は毎フレーム CPU で全機の位置と色を書き換えていた。機数を増やすとそこが天井になる。
`position`（出発点）と `aTo`（行き先）、`aColA/aColB`、`aLag`、`aRnd`、`bright` を属性として渡し、
進み具合 `uProg` だけを毎フレームの uniform で送る。CPU が働くのは図形が変わる瞬間だけになった。

- 機数: 品質1以下 1200 / 品質2 2200 / 品質3 3200（以前は 600 / 1200 / 2000）
- 実測 3200機で 9.6ms/フレーム（1280×820・品質3）。ショーを止めた状態と変わらない
- `__dshow.sample(i)` にシェーダと同じ式の CPU 版を置いた（受け入れテスト用）

### 2. 「どの機体がどこへ行くか」を決め直す（最も効いた変更）
番号順のまま結ぶと経路が何度も交差して、移り変わりが糸くずのように見えていた。

- 両方の図形をヒルベルト曲線の通し番号で並べ替え、同じ順位どうしを結ぶ
- そのうえで、曲線の上で近い者どうし（前後7つ）だけ入れ替えを試す×3周
- 合計移動距離は、でたらめに割り当てた場合の 4割以下になる（`pG-dshow.js` で検査）
- 3200機で15.7ms かかるので、**静止中に次の図形を先に計算しておく**（`dshowPrepare`）。
  切り替わりの瞬間は配列の入れ替えだけで 0.3ms

### 3. 出発の遅れを「場所」で決める（ワイプ）
乱数の遅れだと全体が一様にほどけるだけだった。図形ごとに黄金角ずつ向きを変えた軸に射影して、
端から順に動き出すようにした。隊列が波のように崩れて次の形へ移る。少しだけ乱数を混ぜて境目を消している。
弧の向きも機体ごとに変えてある（`cross(進行方向, z軸) × aRnd`）ので、互いをよけながら流れる。

### 4. 光の描き方（`ShaderMaterial`）
点1つを1枚のガウシアンで描くと平坦に見える。人の目のにじみはガウシアンが約4割で、残りはべき乗の裾。

- 芯 `exp(-d2*30)`（すぐ白に飽和）＋ 裾 `0.075/(1+52*d2)`（遅く落ちる＝これが「明るさ」に見える）
- 明るさは値ではなく**半径**で表す（`pow(bright, 0.42)`）
- `gl_PointSize` は画角を見ない（three.js の `scale` は CSS 高さの半分＝画角90°相当）。
  1mあたりの画素数 `drawingBufferHeight / (2·tan(fov/2))` を自分で渡す
- 2.3px を下限、62px を上限（一部の GPU は 64px で頭打ち）。広げた/詰めたぶんは面積比で明るさを補正する
- `discard` は使わない（タイル方式の GPU で遅くなる）。加算合成は RGB に alpha が掛かるので alpha は 1 のまま
- ブルームは無いので、ゲインは中間バッファが半精度浮動小数のときだけ 2.6、そうでなければ 1.15

### 5. 画の決め方（見える範囲いっぱいに入れる）
以前は「縦長なら 0.78 倍に縮める」＋「`viewScale()` でさらに引く」の二重で、スマホでは実測 204px しかなかった。

- **カメラの距離は 11m で固定**。天球は半径16mなので、これより引くと空が黒いドームになる（実際に出た）
- 代わりに隊列の倍率 `k` を、説明カードと操作列を避けた矩形から決める。
  全幅のシート（スマホ）なら上へ、左に寄った小さなカード（タブレット幅）なら右へ逃がす
- カードの高さは開いたあとに決まるので、矩形が変わったら画を取り直す
- 手前の1機は「カメラからの距離」で置く。見える帯が狭いほど遠くに置いて、画面上の大きさを一定に保つ
- 結果: スマホで約1.8倍、1024px幅で約2.5倍の大きさになった

### 6. ショー専用の機体（`src/showdrone.js`・新規）
主役機（空撮向け・外形854mm・約2200g）とは別に、灯り専門の小型機を作ってショーの間だけ差し替える。
`physics.js` の `applyBody` の末尾で主役機の姿勢を写すので、ホバリングの揺れはそのまま効く。

寸法は国内で実際に使われている機体に合わせた（外形310mm・全高113mm・モーター間232mm・5インチ級・約530g）。
出典は `docs/reference/2026-09-13-show-drone.md`。

### 7. UI の直し
- **ショー中は説明カードを夜の配色にする**。明るいテーマのままだと暗い空の上で白い板が光って見どころを食う。
  `#noteCard` に変数を置き直す方式。ただし**地の文の色は `color: var(--ink)` を明示しないと効かない**
  （変数は使われた場所で解決されるので、`body` で解決済みの色がそのまま降りてくる）
- ショー中は `#viewCol`（視点の切り替え列）を隠す。右に立つ縦長の列は、隊列を写せる幅も高さも削っていた
- 小さな文字に `--accent` を使っていた6か所を `--accent-text` に（明るいテーマで 3.0:1 だった）。
  丸に白抜きの「？」も 3.1:1 だったので地を濃いほうの橙に。`--accent-text` 自体も #b8460f → #a53c09
- 横スクロールする操作列のぼかしを、画面幅の割合から固定長（42px）に。
  割合だと、右端まで送っても最後のボタンが薄いまま残っていた
- `bottomCover()`: 画面の一部しか覆っていないもの（幅の広い画面で左に寄ったカードなど）は、
  真ん中に載っていなければ帯を狭めない

### 8. 見つけて直した不具合
- **自動回転がショー中も効いていた**。`(body.mode === 'idle' || alive.on)` の `alive.on` が条件を素通りさせ、
  5秒後からカメラが回って決めた画が崩れていた。台本がカメラを持つ場面をまとめた `camScripted()` で止める
  （降ろし方・空もよう・一人称・もしも・台本再生も同じ穴があった）
- **`syncBodyMode()` がショー中に `free` へ戻していた**。`free` ではカメラが機体を追いかけるので、
  手前の1機のほうへ注視点が寄って隊列が画面外に出ていた
- ショー機の追従を `stepDshow` でやると1フレーム遅れる。`applyBody` の末尾に移した
- 「輪」の中央の円板が渦の筋に見えていた（角度を等分していた）。黄金角に変更

## B22 スマホで隊列が見えない件の直しと「好きな文字を描く」（2026-09-13実装）

実機（iPhone・Safari）のスクリーンショットで、隊列が**まったく見えていない**ことが分かった。B21 の見積もりが甘かった。

### 何が起きていたか
実機の可視領域は 430×697。そこに **説明カードが350px（50%）** 居座り、
上のバー(77)と操作列(145)を引くと、隊列を出せる帯は **上に59px・下に66px** しか残らない。
`dshowRect()` は「26%を下回ったら 26% に伸ばす」という下限を持っていたので、
**カードの裏に隊列を描いていた**（画面には何も出ない）。

### 直したこと
1. **説明カードを畳めるようにした**（`#noteMini` / `.mini`）。畳むと、いまの図形と数値・本文2行・ボタンだけになる。
   **スマホでは畳んだ状態で始める**（`dshow.mini = narrow()`）。読みたい人が開く
2. 開いていてもショーのカードは **32vh まで**（他の場面は44vh のまま）
3. ショー中の操作列を詰める（見出し「夜」を隠す・上下の余白を減らす）。130px → 106px
4. 結果、帯は 59px → **296px（42%）**、隊列の倍率は 0.34（下限に貼り付き）→ **0.52**

畳んだときは `setNoteMini` から `dshowFrame` を呼んで画を取り直す。カードの高さが変わると帯も変わるため。

### 好きな文字を描く
図形一覧の最後に `custom`（「あなたの文字」）を足した。文字が指定されていなければ順番から外れる（`dshowFigN`）。

- カードの「文字を描く」で入力欄が開く（最大12文字）。決めるとその場でその図形へ飛ぶ（`dshowGoto`／`forceFig`）
- 文字は `localStorage` に残るので、次に開いたときも出る
- 描けるかどうかは実際に点を作ってみないと分からない（絵文字などは拾えない）。
  `dshowFromCanvas` は成否を返し、だめなら元に戻してトーストで知らせる
- 空にして決めると元の6図形に戻る

**大きさの決め方**: 円の図形は縦横どちらかで頭打ちになるが、文字のような横長の図形は余った側を使える。
`dshowFrame` が「いま画面に入る半分の幅・高さ」を隊列の座標系で控え（`dshow.fitX/fitY`）、
文字はその枠に外接矩形を合わせる。スマホでは横に 1.5 倍の余地があり、これを使うと文字が画面いっぱいになる。

**点の配り方**: 無作為に選ぶと縁がぼろぼろになり濃淡の斑も出る。
候補画素を格子のます目に分けて **1ます1点**ずつ選び、ます目の中で少しだけ散らす。
文字が一様な明るさで、輪郭のはっきりした形になる。

**教材としての意味**: 「実際のショーでも、飛ばす前にこの配置を作って全機に読み込ませる（自動操縦）」
「機数は決まっているので、文字が多いほど1文字あたりに使える機体は減る」。
入力欄の下にもこの注記を出している。1200機で5文字（1文字240機）まではよく読める。

### 手前の1機の置き場所
文字は横いっぱいに広がるので、真ん中寄りだと隊列の上に乗る。
帯が狭いほど遠くに置く式の係数を上げ（2.22→2.85・上限7.5m）、位置も隅へ（0.60 / 0.76）。
画面上の大きさは帯の約20%になる。
